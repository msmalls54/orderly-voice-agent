# Agent tool contracts

The machine-readable source is [tool-contracts.json](../contracts/tool-contracts.json). These are narrow business tools, not a shell or generic HTTP proxy.

## Exposed tools

| Tool | Permission | Purpose | Important limits |
|---|---|---|---|
| `find_choices` | Read-only | Find restaurant or menu choices | Maximum three results; query ≤120 characters; session-scoped opaque references |
| `get_previous_order` | Read-only | Resolve “last Tuesday” or another short time reference | Maximum three candidates; no full address/payment/transcript |
| `draft_or_preview` | Reversible cart state | Draft items, set explicit tip, or produce a preview | One store, ≤6 lines, ≤4 each, delivery/ASAP only, total cap |
| `confirm_demo_preview` | Demo state only | Demonstrate exact verbal confirmation | Cannot purchase; exact hash + amount + code; expires in 90 seconds |

## Operations never exposed to the model

- `submit_order`
- `reconcile_order`
- Address creation/change
- Payment-method selection/change
- Promo or credit changes
- Token export/login
- Arbitrary DoorDash command execution
- Arbitrary URL fetch

A future `submit_order` operation is an internal state-machine transition, not an ElevenLabs tool. It is physically absent from the buildathon route table and additionally blocked by `PURCHASE_ENABLED=false`.

## Validation rules

- Reject unknown JSON properties.
- Require UUID request/session identifiers generated by the server, not the caller.
- Opaque `store_ref`, `item_ref`, `order_ref`, `address_ref`, and `payment_ref` expire with the session.
- Natural-language fields are Unicode-normalized, length-limited, stripped of control characters, and never used as shell flags or executable names.
- Monetary values are integer cents. Never accept a model-computed total.
- Limit restaurant/menu choices to three and cart lines to six.
- Support delivery and ASAP only in the MVP.
- Block age-restricted items and requests requiring unverified allergy guarantees.
- Every mutation checks the current cart version and increments it atomically.
- Provider outputs must match a versioned schema. Missing critical money, address, payment, or status fields fail closed.

## Redaction contract

Model/UI-safe outputs may include:

- Restaurant/item display names.
- Quantity and chosen customizations.
- Price components in cents.
- Coarse ETA range.
- Saved-address label plus ZIP suffix, if the caller is in a private setting.
- Payment brand plus last four digits, if returned by the provider.
- Mock/live-read-only marker.

They must not include:

- Full street address, phone number, email, delivery instructions, exact coordinates.
- Full payment identifier, token, card number, CVV, billing address.
- DoorDash access/refresh token, provider cookies, raw provider request/response.
- Unredacted transcript or raw Linkup HTML.
- Internal stack trace, CLI path, command line, environment, or provider IDs.

## Error contract

Every tool returns either:

```json
{
  "ok": true,
  "data": {}
}
```

or:

```json
{
  "ok": false,
  "error": {
    "code": "STALE_PREVIEW",
    "retryable": false,
    "safe_to_speak": "The order changed, so I need to review the total with you again."
  }
}
```

`safe_to_speak` is short, contains no private detail, and gives the caller one next decision. Raw provider errors never cross the gateway.

## Retry rules

- A read-only operation may retry once only for a clearly transient transport error, with a short bounded timeout.
- Cart mutations do not retry automatically unless the provider accepts a caller-controlled idempotency key and its behavior has been locally verified.
- Submit never retries automatically.
- `AMBIGUOUS_SUBMIT` enters reconciliation and blocks every new checkout until status is resolved.

## ElevenLabs tool security

ElevenLabs documents OAuth2 client credentials, bearer tokens, and custom headers for webhook tools. Prefer OAuth2 client credentials with an audience/scope restricted to Orderly tools. Regardless of the credential type:

- Require TLS.
- Rate-limit by credential plus hashed session.
- Require a unique request ID and reject replays.
- Keep tool endpoints separate from health/debug routes.
- Do not place secrets in tool descriptions, model prompts, Lovable code, or URLs.
- Rotate the credential after the event.
